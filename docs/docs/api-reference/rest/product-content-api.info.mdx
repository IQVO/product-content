REST contract of the product-content bounded context of the digital storefront (model: warehouse-docs storefront/model/model.yaml, contexts[product-content], with the FINAL model-gap decisions applied). Product Content enriches the network's catalogue item with description, bullets (&lt; 10), attributes (&lt; 50), media (&lt; 12, URLs to static assets only; upload is out of scope) and the category tree. The title stays the item master's. Content publishes only when complete: a description, exactly one PRIMARY medium and a category. Content lifecycle: DRAFT (revisable, discardable) -&gt; PUBLISHED (revisable, publishable again with the new revision) -&gt; RETIRED (terminal). The category tree is ONE live aggregate without a draft state: every category write applies to the live tree and publishes a new version (CategoryTreePublished). Categories are never deleted. Errors are RFC 9457 problem details (application/problem+json) whose type is /problems/&lt;slug&gt;; shared types are not-found (404), illegal-transition (409), concurrent-update (409) and validation-failed (422), plus one kebab-case slug per Err of the model. Every write takes an Idempotency-Key header (24 hours). No authentication.
